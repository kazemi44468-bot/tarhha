# قواعد توسعه

- هر طرح ابتدا در `tarhha` ثبت می‌شود.
- هر طرح صفحه مستقل و شناسه منوی پایدار دارد.
- دسته‌بندی و منوی مرکزی باید همگام باشند.
- صفحات طرح از `assets/css/sidebar.css` و `assets/js/sidebar.js` استفاده می‌کنند.
- برای طرح‌های بزرگ، ناوبری داخلی و بخش‌های اختصاصی مجاز است.
- پس از بلوغ، پروژه در مخزن مستقل ساخته می‌شود.
- لینک دوطرفه طرح و پروژه ثبت می‌شود.
- تغییرات مهم پروژه به سند طرح بازمی‌گردد.
- هیچ صفحه‌ای نباید منوی مرکزی موازی و ناسازگار بسازد.
- قبل از انتشار هر صفحه، مسیر فونت، منو، لینک‌ها، RTL و نمایش موبایل بررسی می‌شود.

## ثبت وضعیت و حافظه مخزن

- `docs/project-status.md` دفتر وضعیت زنده و مرجع ادامه کار است.
- هر تغییر مهم در ساختار، معماری، منو، طرح‌ها، پروژه‌های مستقل، تصمیم‌های کلیدی یا گام بعدی باید در آن ثبت شود.
- شروع هر کار جدید روی مخزن باید با بررسی `README.md` و `docs/project-status.md` انجام شود.
- وضعیت واقعی GitHub بر حافظه گفتگو مقدم است.
- پس از هر تغییر مهم، فایل تغییرکرده دوباره از GitHub خوانده و صحت آن بررسی شود.
- ادعای تست، اصلاح یا تکمیل فقط پس از بررسی واقعی مجاز است.
- اگر اجرای یک پروژه مستقل باعث تغییر تصمیم یا معماری طرح شود، سند طرح و دفتر وضعیت باید همگام شوند.
